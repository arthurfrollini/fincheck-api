# Spending Q&A Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `POST /assistant/questions` → BullMQ job → Sonnet 5.5 tool loop over three read-only, user-scoped tools → `GET /assistant/runs/:id`; plus a scheduled agent eval (exact numbers + Opus judge).

**Architecture:** New `assistant` feature module. `AgentRun` table for idempotency and status. Tool handlers built per run in a closure over `userId`. Manual loop through `LlmService.complete('agent', …)`. Queue/processor mirror the categorization queue.

**Tech Stack:** NestJS 11, Prisma, BullMQ, `@anthropic-ai/sdk` tool use (`strict: true`), zod, Jest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-16-ai-agent-design.md`

## Global Constraints

- Model `claude-sonnet-5-5`, `output_config: { effort: 'medium' }`, `max_tokens: 4096`, `tool_choice` omitted (auto). No `thinking` param, no sampling params. Judge `claude-opus-5-5`.
- `MAX_STEPS = 6` model calls; `MAX_CONSECUTIVE_FAILED_ROUNDS = 2`.
- Queue `agent`, job `run-agent`, `jobId: agent-run-<runId>`, `attempts: 3`, `backoff: { type: 'exponential', delay: 2000 }`, retention 1 day / 7 days.
- Tool date range ≤ 366 days, `limit` 1–50 (default 20). Tools never accept a user id.
- Assistant `content` appended unchanged; all `tool_result`s of one round in one user message; failed tool → `is_error: true`.
- Never log question, tool inputs or tool results. `LlmFeature` += `'agent'`.
- Fixed answers (pt-BR): step limit, tool failure, refusal, final failure.

## Review Focus

1. **Cross-tenant read**: a tool input carrying another user's `categoryId` must return nothing. Test in Task 3 (e2e-level in Task 5).
2. **Idempotency race**: two concurrent POSTs with the same key must yield one run (unique constraint, P2002 → return existing). Test in Task 1.
3. **Retry after partial run**: a job retried after a model error must not leave `steps` inflated or status stuck in RUNNING. Test in Task 4/5.
4. **Final failure visibility**: when attempts are exhausted the run is FAILED with an answer, not RUNNING forever. Test in Task 5.
5. **Malformed tool input** (dates reversed, range > 366 days, unknown groupBy) → `is_error` result, loop continues. Test in Task 3.
